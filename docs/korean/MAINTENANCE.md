# 버전 유지와 복귀

## 기준과 업데이트 판단

개인용 기준은 `desktop-v0.5.28`, `f87c10895ea35a9a2cea629fef1d7532a3fecbc5`입니다. 2026-10-23 GitHub API 확인에서도 최신 공식 릴리스가 같은 태그여서 새 릴리스로 올릴 작업은 없었습니다. 최신 main에는 릴리스 이후의 변경이 있으므로 버전이 같다는 이유로 main과 같은 코드라고 보지는 않습니다.

업데이트는 별도 브랜치에서 진행합니다.

1. 공식 릴리스·보안 변경·기존 i18n 제안의 병합 상태를 확인하고 기준 SHA를 기록합니다.
2. 적용 전 사용 중인 앱과 개인 프로필을 별도 위치에 보관합니다. 신원 키는 키체인에 유지하고 문서·로그로 내보내지 않습니다.
3. 원본 변경을 선별 적용하고 새 UI 문구를 추출합니다. 내부 enum·명령어·사용자 데이터가 번역 호출에 들어가지 않았는지 diff로 검토합니다.
4. `ko.additional.json`을 수정하고 자원을 재생성합니다. 키·변수 검사, `just ci`, 영향받은 브라우저 흐름과 실제 macOS 패키지 검증을 수행합니다.
5. 같은 demo slug와 bundle ID로 앱을 빌드합니다. 다른 버전의 보조 도구를 혼합하지 않습니다. 기존 앱을 종료한 뒤 새 앱으로 교체하고 서명을 검사합니다.
6. Finder 실행, 언어 변경·재시작, 메시지·파일·시험 에이전트, 원본 앱 복귀를 확인한 후보만 사용합니다.

전용 빌드는 공식 updater 키와 주소를 비우므로 공식 앱이 자동으로 덮어쓰지 않습니다. 앱의 업데이트 화면과 실제 번들 설정도 함께 확인합니다. 새 ad-hoc 서명은 기존 키체인 항목에 대한 macOS의 재승인을 요구할 수 있습니다. 암호나 허용 선택은 사용자가 보안 창에서 직접 처리합니다.

## 복귀와 백업

공식 앱은 `/Applications/LLM/Buzz.app`입니다. 한글판은 공식 앱과 별도 식별자·키체인 서비스·nest를 사용합니다. 기본적인 복귀는 한글판을 종료하고 공식 앱을 실행하는 것입니다. 공식 프로필 위로 한글판 프로필을 복사하지 않습니다.

앱, 공식 앱 데이터, 공용 Buzz 도구 폴더, 원본 nest를 비공개 로컬 폴더에 백업했습니다. 파일 수·바이트 수·SHA-256 트리 집계를 비교했고, 별도 staging 폴더로 복원한 사본도 일치했습니다. 운영 경로에 복원본을 덮어쓰는 시험은 하지 않았습니다. 키체인은 내보내지 않았습니다.

실제로 복구가 필요할 때에는 양쪽 앱을 종료하고 현재 상태를 추가 보관한 뒤, 손상된 항목만 선택해 복구합니다. 백업 이후 생긴 정상 메시지·작업을 오래된 백업으로 덮어쓰지 않습니다. 시험용 로컬 릴레이는 운영 커뮤니티가 아니므로 종료 후 오프라인으로 보일 수 있습니다. 실제 커뮤니티는 사용자가 보유한 초대·접근권한으로 따로 연결합니다.

## 반복 실행 범위

3~5일 실사용과 VoiceOver 직접 검증은 사용자 요청으로 제외했습니다. 미래의 새 릴리스 적용과 공식 PR 제출은 해당 조건이 생겼을 때 수행할 반복·조건부 작업입니다. 감시 자동화나 주기적인 실행은 등록하지 않았습니다.
