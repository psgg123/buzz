공식 개발진의 대상 저장소·번역 구조 확정은 아직 확인되지 않았습니다. 따라서 현재 결과물은 개인 포크의 기여 후보이며 upstream에 PR·댓글을 게시하지 않았습니다. 새 앱으로의 이식은 공식 대상이 정해진 후 키와 화면 문맥을 다시 대응시켜 산정합니다. 0.x에서 새 앱으로 즉시 적용 가능한 패치라고 주장하지 않습니다.

## 변경 묶음

제출 후보는 i18n 기반, 한국어 UI·자원·추출 도구, 별도 보조 도구 탐색 수정으로 나눕니다. 개인용 `build-korean.mjs`, 기본 한국어 빌드 환경, demo identity·업데이트 정책, 개인 검증 기록은 공식 패치에서 제외합니다. 외부 기여자의 출처와 Apache-2.0 고지는 유지합니다.

로컬 `Buzz-Korean-contribution` 폴더의 patch들은 위 기준 태그에 대한 검토용입니다. 최신 main에 그대로 적용된다는 보장은 없으며, 공식 대상 결정 후 새 브랜치에서 재구성·재검증해야 합니다. 개인 계정 키·프로필·백업·릴레이 DB·빌드 바이너리는 이 묶음에 넣지 않습니다.

## PR 초안

제목 후보: `feat(desktop): add Korean UI localization with persistent language selection`

현재 desktop UI의 영문 상수에 번역 호출을 연결하고 한국어 자원을 추가합니다. 설정에서 한국어와 영어를 즉시 전환할 수 있으며, 입력 중인 메시지나 사용자 이름·파일명·코드와 저장된 상태 판정값은 보존합니다. macOS 앱 메뉴와 날짜·알림 표시도 선택한 언어를 따릅니다. 저장 실패는 현재 적용 상태와 구분해 알립니다.

검증에는 저장소 전체 `just ci`, 키·변수 검사, 실제 Tiptap 조합 입력 이벤트, 선택한 기존 브라우저 회귀, macOS 패키지의 언어·메시지·첨부·시험 에이전트 흐름을 포함합니다. 세부 결과와 환경 제약은 `ACCEPTANCE.md`에서 확인합니다. 다른 운영체제의 실제 설치 검증이나 모든 외부 제공자와의 통합 검증은 수행했다고 주장하지 않습니다.

## 제출 전 사람의 확인

현재 및 최신 원본 `AGENTS.md`는 변경 동작에 대한 에이전트 시험 뒤 사람의 직접 시험과 명시적인 확인을 요구합니다. 사람의 시험이 확인되기 전에는 `buzz-review-completed`를 넣거나 ready for review로 표시하지 않습니다.

사용자 확인 순서:

1. Finder에서 개인용 앱을 열고 설정 → 모양 → 언어를 한국어 → English → 한국어로 바꿉니다. 메뉴와 화면이 함께 바뀌어야 합니다.
2. 한글·영문·`{{p0}}`가 섞인 초안을 입력하고 언어를 바꿉니다. 초안이 그대로여야 합니다. 한글 조합을 확정하는 Enter는 메시지를 조기에 보내지 않아야 합니다.
3. 앱을 종료·재실행합니다. 선택한 언어와 같은 신원이 복원돼야 합니다.
4. 시험 공간에서 메시지, 한글 파일명 첨부와 다운로드, 시험 에이전트 시작·중지를 확인합니다.
5. 한글판을 종료하고 공식 앱을 열어 기존 계정과 설정을 확인합니다.

제출 요청과 이 확인을 받은 뒤 공식 대상의 최신 지침·기준 SHA를 다시 확인하고 DCO 서명된 변경으로 PR을 준비합니다. 현재 로컬 자료를 작성했다는 이유로 이 조건을 완료 처리하지 않습니다.
