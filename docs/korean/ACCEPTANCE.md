전체 CI 통과 이후 보조 도구 탐색과 일부 표시 문구 수정이 추가됐으므로 그 영향 검사는 별도 로그로 기록합니다. 마지막 HEAD에서 전체 CI를 다시 돌렸다는 뜻은 아닙니다. 테스트가 의도적으로 출력한 오류 문자열은 실패 건수로 계산하지 않고 결과와 종료 코드를 확인했습니다.

실제 언어 설정 컴포넌트를 마운트한 채 ko↔en 전환, 문서 언어·선택값, 초안·링크·콜백 보존을 검사했습니다. 저장 차단 시 현재 언어를 적용하되 저장 실패를 표시하고, 설정을 다시 열어도 선택과 경고가 유지됩니다. 빈 값·미등록 키·기존 중국어 자원에 없는 문구는 영어로 대체합니다. 사용자 값의 `<b>`, `{{p0}}`, `$t(...)`를 재해석하지 않습니다.

날짜·알림·메모된 라벨이 언어 변경을 따르게 했습니다. Intl의 한글 시간대 표시는 플랫폼 ICU 차이가 있어 날짜 언어와 실제 시간 값도 함께 검사합니다. 900×650, 큰 글꼴·다크 설정 화면에서 수평 넘침이 없었습니다. 첫 개발판의 1280×800·라이트 화면도 별도 기록이 있습니다. 모든 화면·크기 조합의 검증으로 확대하지 않습니다.

앱 소유 접근성 이름·툴팁·메뉴를 번역했습니다. OS 소유 메뉴·파일 창·키체인 창과 외부 프로그램 오류 원문은 시스템/외부 프로그램 언어를 따릅니다.

## 실제 macOS 앱과 로컬 서버

사용자가 신원을 직접 입력한 개인 프로필을 사용했습니다. PostgreSQL·Valkey·공식 소스에서 빌드한 MinIO·실제 0.5.28 relay를 loopback 전용 포트와 별도 데이터 폴더에서 실행했습니다. relay의 S3 조건부 쓰기 적합성 검사를 유지했습니다. 처음 시도한 s3rver는 이 검사를 통과하지 못해 사용하지 않았습니다.

| 흐름 | 관찰 |
|---|---|
| 연결 | 앱이 `ws://127.0.0.1:55639`에 인증·연결하고 fixture 채널 표시 |
| 메시지 | 한글·Settings·`{{p0}}`·파일명·HTML 기호가 섞인 합성 메시지를 앱에서 전송해 DB 저장·화면 표시 확인 |
| 직렬화 | 원래 편집기가 `<`/`>`를 HTML entity로 저장함. raw DB bytes 대신 decode 후 논리적 내용 일치를 검사 |
| 첨부 | 합성 한글 파일명 UTF-8 파일 58 bytes 업로드·전송·다운로드. 양쪽 SHA-256 `efab9dad2848e39bc878b5459c5ec8e7162d3fb15950bf0f3abdc100525d77f2` 일치 |
| 검색 | 실제 relay에서 한글 검색어로 위 메시지 검색 |
| IME | macOS 가입 입력창의 조합 확정 Enter 1회에서 제출·이동 없음. 사용자가 실제 메시지 입력창에서 물리 키보드의 ‘한글’ 조합을 직접 확인했고 AX 초안에서도 관찰. 자동화의 영문 키 단건 입력은 자모로 분리돼 실제 입력 결함과 구분. Tiptap 이벤트 검사에서는 조합 Enter의 전송 차단, 언어 전환 중 편집기/초안 보존, 확정 후 일반 Enter의 1회 전송 확인 |
| 초안·입력 조작 | native ko→en 전환 후 초안 보존. 멘션 열기·Esc, Shift+Enter, `Settings {{p0}} 파일.txt` 붙여넣기 확인. 교체 후 재실행에서도 두 줄 초안 복원 |
| 언어·메뉴 | native 영어 선택 시 화면·메뉴가 영어로 변경. 한국어 선택은 사용자가 직접 수행하고 화면·메뉴 변경을 확인. 이후 앱 교체·실행에서도 한국어와 같은 신원 복원 |
| 오류·접근성 | 로컬 서버 중지 시 연결·메시지 오류, 재시도 후 회복 및 한국어 시간 표시 확인. 설정의 언어 선택 뒤 Tab으로 ‘글래스 배경’에 초점 이동. VoiceOver 읽기 시험은 제외 |
| 에이전트 | 외부 LLM이 필요 없는 deterministic ACP fixture를 사용자 지정 하네스로 등록. native Start/Stop과 실제 ACP initialize·pool ready·relay 연결 확인. 기본 starter의 자동 시작도 관찰해 시험 프로필의 에이전트 모두 중지 |
| 도구 경로 | release에서 개발 checkout의 도구가 먼저 선택될 수 있는 문제 수정. release는 번들 우선, debug는 workspace 우선. 교체한 Downloads 앱이 자기 `Contents/MacOS/buzz-acp`를 자식으로 실행하고 로컬 시험 에이전트가 온라인이 된 뒤 중지되는 것 확인 |
| 알림 | 설정 화면의 OS 권한 상태가 ‘차단됨’이며 한국어 안내와 비활성 상태가 일치. 권한을 변경하지 않았으므로 OS 알림 실제 배달은 미검증. 알림 문구 생성·선택 언어 회귀는 자동 검사 범위 |

메시지 전송·첨부 업로드·검색은 앞선 개발판에서 실제 서버로 검증했고, 이후 교체한 설치본에서 저장된 메시지·첨부·초안·신원의 복원을 재확인했습니다. 사용자가 macOS 키체인 접근을 승인한 뒤 실제 앱 검증을 재개했습니다. 사본 바이트 비교 및 `codesign --verify --deep --strict` 결과와 최종 실행 파일 해시는 로컬 build manifest에 기록합니다.

## 보존·복구와 남은 항목

원본 앱·공식 데이터·공용 도구·원본 nest를 비공개 로컬 폴더로 백업했습니다. 파일 수·크기·트리 해시와 staging 복원 사본이 일치했습니다. 키체인 내보내기나 운영 경로 덮어쓰기는 하지 않았습니다.

재검사에서 공식 앱과 공용 도구는 같았고, 공식 데이터·nest에는 14:43~14:47에 달라진 파일이 있었습니다. agent 구성의 차이는 시작·중지·갱신 시각 각 2건, archive는 이벤트·scope·index 각 2건 증가였으며 관련 로그·retention DB도 달라졌습니다. 전체 데이터가 최초 백업과 바이트 단위로 같다는 주장은 하지 않습니다. 현재 변경을 보존하고 이후 시험 구간의 추가 변화를 따로 비교합니다.

공식 앱 `/Applications/LLM/Buzz.app`을 실제로 다시 실행해 기존 프로필·커뮤니티가 표시되고 온보딩을 다시 요구하지 않는 것을 확인했습니다. 종료 후 공식 앱과 공용 도구의 파일 해시는 같았습니다. 공식 프로필의 agent 실행 시각·로그와 archive DB는 앱의 정상 시작·종료로 바뀌었으며 이를 보존했습니다. 한국어 앱이 공식 프로필을 덮어썼다고 해석하지 않습니다.

남은 실제 확인은 OS가 차단한 알림의 배달과 운영 커뮤니티/기존 에이전트의 개인 프로필 재연결입니다. 사용자 입력 신원과 로컬 시험 환경의 연결까지 확인했으며 운영 데이터 자동 복제·키체인 내보내기는 하지 않았습니다. 정적 추출 결과만으로 모든 도달 가능한 상태의 번역 누락이 0건이라고 단정하지 않습니다. 마지막 native 검증에서 발견한 상수·변수 경유 문구도 수정했으므로 전체 화면 누락 0건 판정과 공식 PR ready는 별도로 남깁니다.

미래 원본 업데이트는 최신 릴리스가 현재 기준과 같아 이번에 적용할 대상이 없습니다. 공식 대상 결정과 별도 PR 제출 요청은 조건부입니다. 사람의 직접 시험 확인 전에는 PR을 ready로 표시하지 않습니다.
