전체 CI 통과 이후 보조 도구 탐색 수정이 추가됐으므로 그 영향 검사는 별도 로그로 기록합니다. 테스트가 의도적으로 출력한 오류 문자열은 실패 건수로 계산하지 않고 결과와 종료 코드를 확인했습니다.

실제 언어 설정 컴포넌트를 마운트한 채 ko↔en 전환, 문서 언어·선택값, 초안·링크·콜백 보존을 검사했습니다. 저장 차단 시 현재 언어를 적용하되 저장 실패를 표시하고, 설정을 다시 열어도 선택과 경고가 유지됩니다. 빈 값·미등록 키·기존 중국어 자원에 없는 문구는 영어로 대체합니다. 사용자 값의 `<b>`, `{{p0}}`, `$t(...)`를 재해석하지 않습니다.

날짜·알림·메모된 라벨이 언어 변경을 따르게 했습니다. Intl의 한글 시간대 표시는 플랫폼 ICU 차이가 있어 날짜 언어와 실제 시간 값도 함께 검사합니다. 900×650, 큰 글꼴·다크 설정 화면에서 수평 넘침이 없었습니다. 첫 개발판의 1280×800·라이트 화면도 별도 기록이 있습니다. 모든 화면·크기 조합의 검증으로 확대하지 않습니다.

앱 소유 접근성 이름·툴팁·메뉴를 번역했습니다. OS 소유 메뉴·파일 창·키체인 창과 외부 프로그램 오류 원문은 시스템/외부 프로그램 언어를 따릅니다.

## 실제 macOS 앱과 로컬 서버

사용자가 신원을 직접 입력한 개인 프로필을 사용했습니다. PostgreSQL·Valkey·공식 소스에서 빌드한 MinIO·실제 0.5.28 relay를 loopback 전용 포트와 별도 데이터 폴더에서 실행했습니다. relay의 S3 조건부 쓰기 적합성 검사를 유지했습니다. 처음 시도한 s3rver는 이 검사를 통과하지 못해 사용하지 않았습니다.

| 흐름 | 관찰 |
|---|---|
| 연결 | 앱이 `ws://127.0.0.1:55639`에 인증·연결하고 fixture 채널 표시 |
| 메시지 | 한글·Settings·`{{p0}}`·파일명·HTML 기호가 섞인 합성 메시지를 앱에서 전송해 DB 저장·화면 표시 확인 |
| 직렬화 | 원래 편집기가 `<`/`>`를 HTML entity로 저장함. raw DB bytes 대신 decode 후 논리적 내용 일치를 검사 |
| 첨부 | 합성 한글 파일명 UTF-8 파일 58 bytes 업로드·전송·다운로드. 양쪽 SHA-256 `efab9dad2848e39bc878b5459c5ec8e7162d3fb15950bf0f3abdc100525d77f2` 일치 |
| 검색 | 실제 relay에서 한글 검색어로 위 메시지 검색 |
| IME | macOS 입력기로 `ㅎ→하→한` 조합, 사용자가 허용한 Enter 1회로 확정. 가입 입력창에서 제출·이동 없음. 실제 Tiptap 이벤트 검사에서는 조합 Enter의 전송 차단, 언어 전환 중 편집기/초안 보존, 확정 후 일반 Enter의 1회 전송 확인 |
| 에이전트 | 외부 LLM이 필요 없는 deterministic ACP fixture를 사용자 지정 하네스로 등록. native Start/Stop과 실제 ACP initialize·pool ready·relay 연결 확인. 기본 starter의 자동 시작도 관찰해 시험 프로필의 에이전트 모두 중지 |
| 도구 경로 | release에서 개발 checkout의 도구가 먼저 선택될 수 있는 문제 수정. release는 번들 우선, debug는 workspace 우선. 최종 패키지의 실행 경로 추가 확인 필요 |

위 native 흐름은 이전 개발판에서 수행했습니다. 최신 소스의 최종 앱을 빌드·복사했고 바이트 비교 및 `codesign --verify --deep --strict`를 통과했습니다. 재시작은 macOS 키체인 응답 대기 중이어서 사용자 직접 승인이 필요합니다. 이를 재시작 통과로 표시하지 않습니다.

## 보존·복구와 남은 항목

원본 앱·공식 데이터·공용 도구·원본 nest를 비공개 로컬 폴더로 백업했습니다. 파일 수·크기·트리 해시와 staging 복원 사본이 일치했습니다. 키체인 내보내기나 운영 경로 덮어쓰기는 하지 않았습니다.

재검사에서 공식 앱과 공용 도구는 같았고, 공식 데이터·nest에는 14:43~14:47에 달라진 파일이 있었습니다. agent 구성의 차이는 시작·중지·갱신 시각 각 2건, archive는 이벤트·scope·index 각 2건 증가였으며 관련 로그·retention DB도 달라졌습니다. 전체 데이터가 최초 백업과 바이트 단위로 같다는 주장은 하지 않습니다. 현재 변경을 보존하고 이후 시험 구간의 추가 변화를 따로 비교합니다.

현재 실제 수용 대기는 새 서명의 키체인 승인 후 최종 앱의 언어·신원·데이터 재시작, 번들 sidecar 실행, native composer IME·키보드·VoiceOver·알림, 공식 앱 복귀입니다. 운영 커뮤니티/기존 에이전트 데이터를 시험 프로필에 자동 복제하지 않았습니다.
